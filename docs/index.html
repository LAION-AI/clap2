1The LAION-Audio-XL Dataset

We collect 1.48B audio samples from YouTube, Common Crawl, web collections and 316 academic datasets, clean and deduplicate them, select for coverage with a 3,718-class taxonomy, and generate short and long captions for clips that lack them.

Taxonomy

A classifier sorts every clip into 3,718 sound classes in 11 groups. Selection thins the common ones: speech falls from 75.3% of the pool to 45.3%.

Claude Sonnet 4.5 grew the hierarchy by assigning captions to leaves and proposing new categories; merging removed duplicates and categories that combine several events. It has 4,416 nodes up to five levels deep, with 837 categories below the 11 groups. The classifier, an MLP on frozen Dasheng-0.6B features, predicts the 3,718 classes of the first three levels and assigns 85.6% of held-out clips to the right group. Clip counts are by predicted label.

How Each Clip Is Captioned

Expert models annotate every clip, and its predicted category decides which specialists run. The captioning model hears the audio, reads the annotations as raw JSON and writes a short and a long caption. Hover or tap an expert or a caption to trace its path.

Compared with Other Corpora

Bars share one linear scale per measure. Captions count the text entries each source reports: GLAP's are mostly ASR transcripts, and SALMONN-2 and Audio Flamingo 3 report training samples without clip counts. Dasheng's mix is audio only.

2Model Architecture

A dual encoder in the CLAP family. The audio tower turns a clip of any length up to 30 s into one vector, the text tower does the same for any text, and the cosine similarity between the two vectors says how well they match: for search, zero-shot classification or as features.

Dual Encoder

Two separate towers, one for audio and one for text, map into one shared space. Because they run independently, audio is embedded once and can then be searched with any text. Hover a block for details.

Block heights follow each tower's width. Widths and depths follow common small ViT shapes and stay hardware-aligned. Both towers use pre-norm RMSNorm blocks with SwiGLU and rotary position embeddings.

Flexible Length Encoding

No fixed window: each clip is read at its own length, without padding or cropping. Every 16 × 16 spectrogram patch becomes one token, so a short clip stays short.

128 mel bins at 100 frames per second: 8 tokens every 160 ms. Training clips are at most 30 s (1,504 tokens); longer inputs work but are outside the training range. Attention cost grows with the square of the token count.

3Scaling Laws

We train five model sizes from scratch, each on 1M to 1,024M samples seen, and fit how the error on MAEB-30 falls with training compute. MAEB-30 is the Massive Audio Embedding Benchmark: 30 tasks across speech, music and environmental sound.

Error Falls Predictably with Compute

Each line is one model size, moving right as it sees more samples. Each doubling of compute lowers the error by 4.1%, about +1.9 MAEB-30 points at the largest budget.

Runs see 1M to 1,024M samples. The dashed line marks the lowest error reached so far. The fit shows its 95% bootstrap interval, all runs as faint dots, and the compute-optimal runs behind it as solid dots. Fitted exponent: α = 0.0603.

4Benchmark Results

LAION-5B and OpenCLIP gave vision open web-scale data and reproducible scaling laws. LAION-Audio-XL and CLAP2 bring the same to audio, with the best MAEB-30 score of any model trained from scratch.

A Step Change for CLAP

MAEB-30 scores of CLAP-style models by release date. Four years raised the best score by 16 points, from 28.3% to 44.1%. CLAP2 adds 9.5 more.

Dates are first public releases (paper or checkpoint). Omni-embedding models with 1B to 9B parameters, which are not drop-in CLAP replacements, reach up to 53.5% (LCO-Embedding-Omni-7B); they appear in the size comparison below.

5Usage

Use CLAP2 and LAION-Audio-XL with only a few lines of code.

Use CLAP2

# pip install torchaudio tiktoken soundfile
# pip install "open_clip_torch[audio] @ git+https://github.com/mlfoundations/open_clip@refs/pull/1230/head"
import torch, open_clip as oc, soundfile as sf

hub = "hf-hub:laion/clap2-medium-audioxl-s1B"
m, prep = oc.create_model_from_pretrained(hub)
tok = oc.get_tokenizer(hub)

w, sr = sf.read("dog.wav", dtype="float32")
x = prep(m.audio.cfg.audio_seq_len)((torch.from_numpy(w.T), sr))
a = m.encode_audio({k: v[None] for k, v in x.items()})
t = m.encode_text(tok(["a dog barks", "rain falls"]))
print(torch.cosine_similarity(a, t))
from torch.nn.utils.rnn import pad_sequence

xs = []
for f in ["dog.wav", "rain.wav"]:
    w, sr = sf.read(f, dtype="float32")
    xs.append(prep(m.audio.cfg.audio_seq_len)((torch.from_numpy(w.T), sr)))
# clips differ in length: pad to the longest, the padding is masked
batch = {k: pad_sequence([x[k] for x in xs], batch_first=True) for k in xs[0]}
a = m.encode_audio(batch)
print(torch.cosine_similarity(a[:, None], t[None], dim=-1))

Use LAION-Audio-XL

Three configs by licence: open (the default), sharealike and noncommercial. Clips we crawled ourselves are listed as links in the gated laion/laion-audio-xl-links.

from datasets import load_dataset

name = "laion/laion-audio-xl"
ds = load_dataset(name, streaming=True)
for s in ds["train"].take(3):
    print(s["short_caption"], s["duration"])
def is_music(s):
    return s["tax_l1"] == "Music"

music = ds["train"].filter(is_music)
for s in music.take(3):
    print(s["pred_tempo_bpm"], s["music_key"])
